# pixel-forge

> Turn one product photo into a full color-variant catalog in seconds. Pillow-based, deterministic, no LLMs, no cloud.

[![Python](https://img.shields.io/badge/Python-3.10+-3776AB.svg)]() [![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

---

## What it does

You hand `pixel-forge` a base product photo and a variants config:

```yaml
# variants.yaml
input: base-shirt.png
output_dir: out/
target:
  type: hsv_range
  hue: [340, 360]      # the red of the original shirt
  saturation_min: 0.4
variants:
  - name: navy
    target_hue: 220
    target_saturation: 0.8
  - name: forest
    target_hue: 140
    target_saturation: 0.55
  - name: charcoal
    target_hue: 0
    target_saturation: 0.02
    target_value_shift: -0.15
```

Then:

```bash
pixel-forge build variants.yaml
```

And get back:

```
out/
├── base-shirt-navy.png
├── base-shirt-forest.png
└── base-shirt-charcoal.png
```

Each variant is generated by **isolating the target color range, preserving lighting/highlights**, and remapping the hue/saturation in HSV space. The result keeps shadows, gradients, and texture — it just changes the color of the product. ~30ms per image on a modern laptop.

---

## Why I built this

Running DarkForge AI's e-commerce projects, generating photo variants for SKU catalogs was eating hours per session in Photoshop. `pixel-forge` automates the deterministic 90% so I can spend the saved time on the 10% that actually needs a human (compositing, color-matching against real fabric).

The core trick is doing the recolor **in HSV space** instead of RGB:

- **Hue** controls *which* color it is — easy to swap.
- **Saturation** controls *how much* color.
- **Value (brightness)** controls the lighting and is what you preserve.

That's why a navy variant generated from a red shirt still looks photographed-in-a-studio rather than Photoshop-bucket-filled.

## Install & run

```bash
pip install pixel-forge

# build all variants
pixel-forge build variants.yaml

# preview a single variant without writing
pixel-forge preview variants.yaml --variant navy --show
```

Requires Python 3.10+ and Pillow. No external services.

## How it works

```
┌──────────────┐
│  base image  │
└──────┬───────┘
       │ RGB → HSV
       ▼
┌──────────────┐    target_hue
│ select pixels│◄── target_saturation_min
│  in hue band │
└──────┬───────┘
       │ mask
       ▼
┌──────────────┐
│ remap hue    │    new_hue
│ scale satur. │    new_saturation
│ shift value  │    new_value_shift
└──────┬───────┘
       │ HSV → RGB
       ▼
┌──────────────┐
│ output png   │
└──────────────┘
```

The recolor preserves the *relative* lighting of every pixel — only the hue and saturation are remapped. That's what makes it look like a real product photo and not a Photoshop bucket fill.

## API for direct programmatic use

```python
from pixel_forge import recolor

out = recolor(
    "base-shirt.png",
    source_hue_range=(340, 360),  # current red
    target_hue=220,                # navy
    target_saturation=0.8,
    min_saturation_to_recolor=0.4, # avoid recoloring greys/whites
)
out.save("navy-shirt.png")
```
